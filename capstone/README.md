# Capstone Project (Optional)

**This is not required.** The capstone is entirely optional. It is designed for participants who have completed the core workshop and at least 3 self-paced builds, and want a larger challenge.

---

## What Is the Capstone?

Build a tool that solves a **real problem** in your current PM role. Not a tutorial. Not an example. Something you will actually use.

The capstone is different from the workshop builds in three ways:

1. **You define the problem.** The workshop gives you a spec. The capstone starts with a blank page and a problem you care about.
2. **You design the solution.** The workshop tells you what criteria to use and what the output should look like. The capstone requires you to make those decisions.
3. **The output is useful.** The workshop builds are learning exercises. The capstone produces a tool you bring to your next sprint planning, stakeholder meeting, or analysis session.

---

## When You Are Ready

Complete at least **3 self-paced builds** from the `build/` folder before attempting the capstone. You should feel comfortable with:

- Writing prompts that produce working code on the first or second try
- Iterating on output with targeted follow-up prompts
- Testing tools with real-ish inputs and verifying the results
- Debugging common issues (wrong output, missing features, formatting)

If you are still fighting syntax errors or struggling to get basic tools working, do more builds first. The capstone assumes fluency with the vibe coding loop.

## Two Tracks

Choose based on what you need most right now:

### Track A: Interactive Prototype

Build an interactive prototype of a real feature you are working on or evaluating. Users can click through it. Stakeholders can see it. You can test it.

**Best for:** PMs who need to demonstrate a concept, run user testing, or build a demo.

[Track A Guide →](track-a-prototype.md)

### Track B: Data Analysis Tool

Build a tool that analyzes real product data and produces insights you will use in your next planning cycle. Automate a recurring analysis or answer a question that has been sitting in your backlog.

**Best for:** PMs who work with data regularly and want to automate something tedious.

[Track B Guide →](track-b-data-tool.md)

## How Long It Takes

**2-4 hours of focused work.** This is not something you finish in a single sitting unless you have a very clear idea going in.

A typical timeline:

| Phase | Time | What You Do |
|---|---|---|
| Define the problem | 30 min | Identify the real problem, sketch the solution |
| Build the shell | 45 min | First working version with core logic |
| Add features | 60 min | Polish, additional capabilities, better output |
| Test and refine | 45 min | Test with real data, fix issues, iterate |
| Document and share | 30 min | Write up what you built and what you learned |

## How to Share

When you finish your capstone, share it with the community:

1. Use the [showcase template](../community/showcases/TEMPLATE.md)
2. Fill in what you built, why, and what you learned
3. Submit to `community/showcases/`

Sharing is optional, but it helps other PMs see what is possible and gives you feedback on your work.
