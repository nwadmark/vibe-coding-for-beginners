# Code of Conduct

## Our Pledge

We are committed to making this workshop and community a welcoming, inclusive space for everyone — regardless of experience level, technical background, job title, or tool preferences.

This project exists to help product managers learn new skills. That mission only works if everyone feels safe to ask questions, make mistakes, and share their work.

---

## Our Standards

### Be Welcoming

- Welcome people of all PM experience levels — from first-year APMs to VPs of Product
- Welcome people of all technical backgrounds — from "never touched code" to "used to be an engineer"
- Use language that is accessible to non-technical audiences
- Remember that everyone starts somewhere

### No Gatekeeping

- Do not dismiss tools or approaches because they are "not real coding"
- Do not tell someone their tool is "too simple" — simple tools that solve real problems are the point
- Do not correct someone's prompt style unless they ask for feedback
- "There is no wrong way to vibe code" — if it works, it works

### Respect Tool Preferences

- Do not argue that Claude is better than ChatGPT (or vice versa)
- Do not insist that someone switch from Replit to Cursor (or vice versa)
- Recommend tools based on the person's needs, not your preferences
- All tools mentioned in this workshop are valid choices

### Be Patient with Beginners

- Answer questions without condescension
- If someone is stuck, help them — do not just point to documentation
- Remember that error messages are intimidating when you have never seen one before
- Celebrate small wins — getting a tool to run for the first time is a big deal

### Give Constructive Feedback

- When reviewing showcases or contributions, focus on what works first
- Suggest improvements as options, not mandates: "You might also try..." instead of "You should..."
- Be specific: "The bar chart alignment could be fixed by..." instead of "This needs work"
- Remember that the person behind the code put in real effort

---

## Unacceptable Behavior

- Harassment, discrimination, or exclusion of any kind
- Dismissing someone's work or questions as "too basic"
- Gatekeeping about what counts as "real" programming or coding
- Sharing someone's private data or code without permission
- Trolling, insults, or personal attacks
- Sustained disruption of workshop sessions or community discussions

---

## Scope

This Code of Conduct applies to:
- Workshop sessions (in-person and virtual)
- GitHub issues, pull requests, and discussions
- Community showcases and case studies
- Any communication channel associated with this project

---

## Enforcement

Instances of unacceptable behavior can be reported to the project maintainers. All reports will be reviewed and handled with discretion. Maintainers have the right to remove, edit, or reject contributions that violate this Code of Conduct.
